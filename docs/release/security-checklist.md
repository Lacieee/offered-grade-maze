# Security and privacy checklist (CP10 B4)

Release 1.0.0, branch `feat/CP10-debug-view-hardening-release`. Reviewed 2026-10-14 against
the built server (`node packages/server/dist/main.js`, rate limits on) and the code. The
game runs locally only (PD4): there is no login, no personal data and no cloud deployment.

| #   | Check                               | Result                     | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --- | ----------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **Zod validation on every route**   | ✅                         | `packages/server/src/routes/api.ts`: every route declares `params`, `querystring` and `body` Zod schemas from `@ogm/shared` (`CreateGameRequestSchema`, `TransitionRequestSchema`, `CompleteRequestSchema`, `GameParams` (UUID), `RoomsQuery`, `ClientErrorRequestSchema`); `/health` takes no input; unknown routes answer 404 in the error format. Tests: `games.test.ts` "400 invalid_seed …", "400 for a malformed body", "400 for malformed or too many ids …", "404 unknown game, 400 malformed id". Live: `POST /games {"difficulty":"insane"}` → 400 `invalid_request`; `POST /games/not-a-uuid/start` → 400 `Invalid UUID`. |
| 2   | **Body limits**                     | ✅ (fixed)                 | 16 kB on every route (`BODY_LIMIT` in `app.ts`), 8 kB on `/client-errors`. The review found `POST /games` accepting a 300 kB body (Fastify's 1 MiB default); fixed with a failing test first: `games.test.ts` "every game route refuses bodies over 16 kB with 413 (CP10 B4)".                                                                                                                                                                                                                                                                                                                                                       |
| 3   | **Rate limits active**              | ✅                         | `@fastify/rate-limit`, per route (`RATE_LIMIT_ENABLED=true` by default). Live: 40 × `POST /games` in a row → 17 × 201, then 429. Test: `ratelimit.test.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 4   | **Helmet headers present**          | ✅                         | Live `GET /`: `Content-Security-Policy` (`default-src 'self'`, `script-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, …), `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy` and `-Resource-Policy: same-origin`, `X-DNS-Prefetch-Control: off`, `X-Download-Options`, `X-Permitted-Cross-Domain-Policies`, `Origin-Agent-Cluster`. No HSTS on purpose (plain HTTP on localhost, PD4). Test: `static.test.ts`.                                                                                                                              |
| 5   | **No stack traces in responses**    | ✅                         | `errors.ts`: every error answers `{ error: { code, message } }` in English; 5xx answer `internal` / "Internal server error." and are logged server-side only. Live: malformed JSON → 400 `bad_request` with a one-line message. Test: `games.test.ts` "unknown API routes answer 404 in the error format", "a stored level hash that no longer matches answers 500 level_drift".                                                                                                                                                                                                                                                     |
| 6   | **No IP or user agent stored**      | ✅                         | Database (`db/schema.ts`): `games`, `results` and `game_transitions` hold seeds, rooms, doors, times and flags only. Logs: the request serializer keeps method, URL and request id only ("No IP addresses or user agents in the logs either"); `trustProxy: false`. Client error reports are logged as sent (message, stack, context) and contain no IP or user agent.                                                                                                                                                                                                                                                               |
| 7   | **Game ids are random UUIDs**       | ✅                         | `GameService.create`: `randomUUID()` (Node `crypto`, v4); results the same. Seeds use 40 bits from `randomBytes`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 8   | **`DEBUG_VIEW_ENABLED` documented** | ✅                         | `README.md` (How to play → Debug view; Configuration table), `docker-compose.yml`, `docs/architecture.md`. Default `true` (PD6); `false` makes `GET /games/:id/debug` answer 404 (test: "404 when the debug view is disabled"). The client shows "could not be loaded" in the debug view then.                                                                                                                                                                                                                                                                                                                                       |
| 9   | **Dependencies audited**            | ✅ (1 moderate, justified) | `pnpm audit` (2026-10-14): **0 critical, 0 high**, 1 moderate: GHSA-67mh-4wv8-2f99, esbuild ≤ 0.24.2 lets websites read responses of esbuild's _development server_. Path: `packages/server > drizzle-kit@0.31.11 > @esbuild-kit/esm-loader > esbuild@0.18.20`. `drizzle-kit` is a dev dependency used only to generate migrations (`pnpm --filter @ogm/server db:generate`); it never runs esbuild's dev server, and it is not in the Docker image's runtime. Accepted; revisit when drizzle-kit drops `@esbuild-kit`.                                                                                                              |
| 10  | **Release build has no test hook**  | ✅                         | `window.__ogm` is undefined in the production build; `?autopilot=1` exposes only `{ autopilot }`. e2e: `release.spec.ts`. The test hook (`src/dev/testHook.ts`) is not in the bundle (checked: no `maskSurfaces`/`goalScreen` in `dist/assets`).                                                                                                                                                                                                                                                                                                                                                                                     |
| 11  | **Server-side game rules**          | ✅                         | Crossings are validated against the house (desync on an impossible move), completion requires the goal room and no pending transitions, the client time is only official within 0–5 s of the server's (CP07). Tests: `games.test.ts` transitions and completion blocks.                                                                                                                                                                                                                                                                                                                                                              |

**Open blockers:** none.
